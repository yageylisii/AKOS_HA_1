# HA4: канатная дорога, вариант 46

Клиент-серверная имитационная модель на C11 и TCP/IPv4. Оператор, две станции с семействами пассажиров и каждая кабина работают отдельными процессами. Наблюдатели получают общий журнал и сводное состояние. Сервер сохраняет состояние при отключении участников.

## Быстрый запуск

Нужны Linux или macOS, C-компилятор и Make. Для автоматического запуска и сетевых тестов нужен Python 3.9+. У самих пяти программ Python-зависимостей нет.

```sh
cd HA4
make
make run
```

`make run` выбирает свободный локальный порт, запускает все роли и наблюдателя, показывает события в процессе работы. Журналы сохраняются в `logs/local/`. Ctrl+C останавливает запуск и освобождает запущенные им процессы.

Быстрый набор без ветра и поломок, питон скрипты запускают программу с готовыми данными:

```sh
./scripts/run_local.sh --config settings_small.txt --delay 50
```

Можно задать `--port 4546`. Параметры скрипта передаются непосредственно скрипту, не `make run`.

## Запуск в отдельных терминалах

Сначала сервер, затем клиенты в любом порядке; модель начнётся после регистрации всех обязательных ролей. В этом примере в конфигурации две кабины:

```sh
./cc_server 4546 --host 0.0.0.0 --config scripts/settings_small.txt --seed 12345 --delay 150 --log logs-server.txt
```

```sh
./cc_operator 127.0.0.1 4546
./cc_station 127.0.0.1 4546 A
./cc_station 127.0.0.1 4546 B
./cc_cabin 127.0.0.1 4546 1
./cc_cabin 127.0.0.1 4546 2
./cc_observer 127.0.0.1 4546
```

Каждую строку запускают в своём терминале. Можно открыть несколько наблюдателей. `--no-board` отключает таблицы наблюдателя, оставляя события. `--log ФАЙЛ` сохраняет вывод любого клиента. `--wait С` задаёт ожидание запуска сервера (по умолчанию 10 секунд). Номер кабины можно опустить: сервер выберет первый свободный слот. Станция задаётся `A`/`B` или `1`/`2`.

На другой машине вместо `127.0.0.1` нужно указать IPv4-адрес или имя компьютера с сервером. На сервере должен быть разрешён входящий TCP-порт. Все программы собирают из одной версии исходников; сетевой формат не зависит от выравнивания C-структур. Дополнительный запуск всех клиентов против уже работающего сервера:

```sh
python3 scripts/remote_clients.py 192.168.1.10 4546 --cabins 2
```

## Остановка и восстановление

- `s` или `status` в консоли сервера: сводное состояние.
- `q`, `quit`, `stop`, Ctrl+C или SIGTERM серверу: эвакуация, итоговая статистика, сообщение SHUTDOWN всем клиентам и завершение.
- Ctrl+C клиенту: отключить только этого клиента. Отключение наблюдателя не останавливает дорогу. При потере обязательного участника сервер приостанавливает модель, сохраняя пассажиров и кабины. Запуск той же роли с тем же номером продолжает работу.
- Зависший участник отключается после 10 секунд без ответа. Клиент без HELLO также отключается через 10 секунд. Медленный получатель не блокирует цикл сервера: отправка идёт через ограниченную неблокирующую очередь.
- После закрытия входа сервер доставляет принятых пассажиров и завершает работу. Защита от бесконечного ожидания: аварийная эвакуация через 43200 модельных секунд после закрытия входа.

```sh
make demo-reconnect
```

Демонстрация отключает и снова подключает кабину и наблюдателя; журнал — `logs/demo-reconnect/`.

## Конфигурация

Без `--config` сервер задаёт вопросы интерактивно. В файле одно значение на строку; пустые строки и комментарии `#` разрешены. Время — в модельных секундах от 09:00, вероятности — с точкой.

| № | Значение | Диапазон |
|---|---|---|
| 1 | Число кабин | 1–12 |
| 2 | Вместимость кабины | 1–20 |
| 3 | Максимум пассажиров | 0–200 |
| 4 | Продолжительность приёма | 1–43200 с |
| 5 | Путь между станциями | 1–1800 с |
| 6 | Длительность поломки | 1–300 с |
| 7 | Интервал прибытия | 1–3600 с |
| 8 | Пассажиров за интервал суммарно | 1–20 |
| 9 | Посадка одного пассажира | 1–60 с |
| 10 | Высадка одного пассажира | 1–60 с |
| 11 | Доля VIP | 0–1 |
| 12 | Вероятность поломки за модельную минуту | 0–0.5 |
| 13 | Порог остановки по ветру | 1–150 м/с |
| 14 | Число интервалов ветра | 0–3 |

Затем для каждого интервала: начало, конец и скорость (0–150 м/с), каждое значение с новой строки. Интервал включает начало и не включает конец. Вне интервалов скорость равна нулю; при пересечении интервалов остановка действует, если хотя бы один достигает порога. При скорости, равной порогу, движение останавливается.

**Формат обновлён:** в отличие от исходного черновика добавлены порог и скорости интервалов. Все комплектные файлы обновлены; старые конфигурации надо дополнить. Протокол версии 2 несовместим с бинарными файлами исходного черновика.

`--seed ЧИСЛО` обеспечивает воспроизводимость модели, `--delay МС` (0–5000) регулирует паузу между группами событий, `--no-delay` убирает паузы. Для всех параметров сервера: `./cc_server --help`.

## Проверки

```sh
make test                 # модель, протокол, 12 сетевых сценариев
make test-linux           # тот же набор в Docker с Linux/GCC
make test-distributed     # сервер и клиенты в разных Linux-контейнерах
```

Для двух последних команд нужен запущенный Docker. `test-distributed` создаёт временную сеть и удаляет свои контейнеры/сеть после завершения. Программы в контейнере работают на C; Python используется только для запуска тестов. При первом запуске Docker скачивает базовый образ и пакеты компилятора.

Ожидаемые отказы неверным входным данным печатают `Condition ... failed`; успех определяется завершающими строками `Model tests passed`, `Protocol tests passed`, `Network tests passed` и кодом возврата 0. Результаты сетевых проверок: `logs/test-results.json`, журналы каждого процесса — в `logs/test-*/`.

Полный отчёт, архитектура и фактические результаты находятся в `REPORT.md`.
